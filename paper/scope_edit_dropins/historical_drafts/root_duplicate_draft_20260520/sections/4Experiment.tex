\section{Experimental Setup}\label{sec:experiment}

\subsection{Benchmarks}

The current exact-scored main matrix contains four legal benchmarks. CaseHOLD
and LegalBench-SCALR are not in this main matrix; they are historical
provenance unless explicitly re-added.

\paragraph{BarExamQA.}
BarExamQA contains 1,195 multiple-choice bar-exam questions in the active full
split. The task is answer selection over four options, scored by exact answer
letter. Retrieval uses a frozen legal-passage collection with aligned gold
passage ids. This dataset is the clearest case where raw-question retrieval is
weak and generated legal query handles can matter.

\paragraph{HousingQA.}
HousingQA contains 6,853 yes/no statutory entailment questions. The corpus is a
large state-housing-statute collection. Some rows have multiple gold statutes,
so retrieval exposure is interpreted as any-gold exposure in the main tables.
The signed Housing rows also carry the practical cache caveat that full
golden-neighbor retrieval uses stored gold embeddings and a cross-encoder input
cap for retrieval-cache construction.

\paragraph{Legal-Link-EU.}
Legal-Link-EU contains 1,127 four-way multiple-choice legal-link prediction
questions over a frozen EUR-Lex evidence corpus. Rows ask which legal
relationship holds between EU legal documents. The retrieval cache records
source-document and target-document hits in addition to Hit@5/MRR@5. The
current signed runs use \method{CROSS\_ENCODER\_MAX\_CHARS=22000} so long EU
legal documents can be reranked without silent truncation of model-facing
evidence.

\paragraph{MASLegalBench.}
MASLegalBench contributes 303 exact-scored multiple-choice questions over a
frozen corpus of penalty-notice source material. It has no official
per-question gold passage ids. Therefore, MAS retrieval values in this paper
are same-source-document proxies, not gold-passage Hit@k.
\method{golden_passage} and \method{golden_plus_neighbors} are marked not
applicable.

\subsection{Models and Providers}

The current grid uses three API-backed model/provider labels:

\begin{itemize}[leftmargin=*]
\item \method{groq-llama8b}: Llama 3.1 8B Instant, the small-model axis.
\item \method{or-gemma4-26b}: Gemma 4 26B through OpenRouter, usually pinned to
same-model provider routes when needed.
\item \method{groq-llama70b}: Llama 3.3 70B Versatile, the larger-model
cross-family axis.
\end{itemize}

Provider labels are part of the result identity. Mixed or repaired rows are
kept only when the signoff log records the same model/provider intent,
non-overlapping row repair, and no silent fallback. This is why many signed
rows are citable with caveats rather than simply marked clean.

\subsection{Build and Reproducibility}

Paper-local plots and tables are regenerated by:

\begin{verbatim}
python3 paper/build_current_paper_assets.py
\end{verbatim}

The script reads \claimgate and writes only into \method{paper/figures},
\method{paper/tables}, and \method{paper/current_signed_rows.csv}. The root
paper can then be compiled with \method{tectonic main.tex} from
\method{paper/} or with the standard \method{pdflatex}/\method{bibtex}
sequence. The generated figures intentionally retain the signed-row caveats:
missing rows remain missing, MAS retrieval is marked as a proxy in captions and
tables, and answer rows are not silently filled from older CaseHOLD/SCALR
artifacts.
