# Router Probe Findings - 2026-04-30

This note records the first offline test of whether the evidence-budgeted router
idea is learnable from cheap features, rather than merely attractive as an
oracle.

## Setup

Common-arm experiment: `rag` vs `two_call` across four N=200 slices:

- MuSiQue Llama 70b
- BarExam Gemma 4 26B
- CaseHOLD Llama 70b
- LegalBench-SCALR Llama 70b

Input detail logs:

| BarExam Gemma 4 26B | `logs/eval_rag_simple_or-gemma4-26b_20260428_0231_detail.jsonl` | `logs/eval_rag_snap_hyde_2call_or-gemma4-26b_20260428_1435_detail.jsonl` |
| CaseHOLD Llama 70b | `logs/eval_rag_simple_groq-llama70b_20260428_0259_detail.jsonl` | `logs/eval_rag_snap_hyde_2call_groq-llama70b_20260428_0309_detail.jsonl` |
| LegalBench-SCALR Llama 70b | `logs/eval_rag_simple_groq-llama70b_20260428_1508_detail.jsonl` | `logs/eval_rag_snap_hyde_2call_groq-llama70b_20260428_1520_detail.jsonl` |

Generated by `scripts/build_router_training_set.py` and evaluated by
`scripts/train_router_baseline.py`.

The router sees static task features and cheap retrieval-probe fields:

- answer format, question length, choice length, named-entity/legal-term counts,
  multi-hop cue count;
- retrieval evidence count and max cross-encoder score.

Dataset, provider, and subject metadata are excluded in the default report so
the probe tests transferable task/evidence signals rather than provenance
shortcuts.

The policy reward is:

```text
correct - 0.02 * llm_calls
```

## Interpretation

This is not yet a deployable router result. It is a useful negative/diagnostic
result:

1. **Oracle headroom is real**: per-question method complementarity exists.
2. **Static cheap features are insufficient**: a one-rule router does not
   generalize cleanly across legal datasets.
3. **Dataset-level bottlenecks dominate**: MuSiQue wants `two_call`; CaseHOLD
   and SCALR usually want `rag`; BarExam has rare but valuable `two_call` wins.
4. **The online controller needs richer state**: not just question shape, but
   evidence state, support/contradiction, answer stability, and whether the
   retrieved evidence can change the decision.

This supports the combined router + ledger direction. If a cheap router cannot
reliably identify the valuable flips from prompt shape alone, the system needs
to expose structured evidence state before escalating.

## Literature Fit

The current literature already covers broad adaptive and multi-agent RAG:

- MBA-RAG treats retrieval methods as bandit arms and uses a reward balancing
  answer quality and retrieval cost. Our angle should not merely duplicate this;
  it should specialize the reward/state to legal evidence and bottleneck type.
- Agentic RAG survey/future-work language emphasizes reasoning efficiency,
  retrieval efficiency, adaptive retrieval control, dynamic tool selection,
  retrieval planning, and adaptive orchestration.
- L-MARS shows exactly the legal-domain asymmetry we see locally: agentic
  retrieval helps current-law questions but provides negligible gains on
  Bar Exam QA.
- Legal RAG Bench argues for factorial retrieval/generator decomposition and
  finds retrieval often sets the ceiling in long-form legal RAG.
- MA-RAG, RAGentA, and MASS-RAG show that multi-agent RAG role decomposition is
  already crowded; role decomposition alone is not a strong novelty claim.
- ACC-RAG and related context-compression work show another neighboring axis:
  adapting context budget, not method/agent budget.

## Better Claim

The compelling claim is not:

> We built a legal RAG agent.

It is:

> Legal RAG needs evidence-budgeted orchestration: the controller must choose
> when retrieval or multi-agent processing is worth its cost, and the agents
> must share structured evidence state so escalation decisions are based on
> what the evidence supports, contradicts, or leaves unknown.

This is both more legal-specific and more scientifically testable.

## Next Test

The next router table should add features that are closer to the proposed
controller:

- direct-answer stability across two cheap samples;
- whether retrieved evidence lexically overlaps the chosen answer option;
- whether the final answer changes between k=1 and k=5;
- source disagreement / contradiction flags;
- ledger fields from a small `ledger_subagent_rag` prototype.

If those features do not improve leave-one-dataset-out behavior, then the
router story should be downgraded and the paper should focus on the diagnostic
taxonomy plus shared evidence ledger.
